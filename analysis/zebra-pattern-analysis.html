5. 怎么读这张表

  1. 方向性改动只看 defensible 为 true 的模式。recurring 只是词法事实：同一条证据被两个案例引用，算一次观察，不算两次复现。
  2. defensible 要求去掉共用证据、并剔除自报安装版本未建立的引用之后，独立支撑仍达门槛。
  3. 每个 recurring 模式对应一处结构性改动，目标是让一批案例同时消解，而不是逐条修补。
  4. 本表是词法规则，不是语义判断；复现不等于文档有错，仍需人工与真机验证。

复现只说明该处值得文档复核，不证明文档本身有错，也不证明哪个参数在设备上正确。名义复现不等于可汇报方向。

6. 给站点接入方的要求：把 57 条公开论坛案例喂进 Track A

Track A 现在唯一可行的素材，是站点上那 57 条来自开发者论坛的公开案例（ZF-<16hex>）。定性必须准确：它们是真实第三方上报，不是 SPR（SPR 指涉及产品行为的客户支持工单）。它们能支撑“人能否独立找到答案”，不得称为 SPR。
